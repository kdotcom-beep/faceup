# WCAG 2.2 Level A and AA criteria

Every Level A and AA success criterion: the Face Up rules that cover part of it, what the scanner checks for it, how the rest is decided, and a manual test for a person.

- **1.1.1 Non-text Content** (Level A). No Face Up rule. Scanner: axe checks whether each image has alt text. It cannot check whether the alt text is correct. The rest is decided by a person. Manual test: Turn on a screen reader, the software that reads a page aloud for people who are blind or have low vision. Listen to what it says for each image, icon and chart, and check the words tell you what the picture does. The screen reader should skip purely decorative images.
- **1.2.1 Audio-only and Video-only (Prerecorded)** (Level A). No Face Up rule. Scanner: no check. The rest is decided by a person. Manual test: Play each recording that has only sound, or only moving pictures with no sound. Check there is a text version, such as a transcript, that gives the same information. A video with no sound can have a spoken audio version instead.
- **1.2.2 Captions (Prerecorded)** (Level A). No Face Up rule. Scanner: no check. The rest is decided by a person. Manual test: Watch each recorded video with the sound off. Check the captions show all speech and the important sounds, such as a doorbell or laughter, and keep time with the video.
- **1.2.3 Audio Description or Media Alternative (Prerecorded)** (Level A). No Face Up rule. Scanner: no check. The rest is decided by a person. Manual test: Play each recorded video and listen without watching. Check that an audio description, a spoken account of what happens on screen, or a full text version tells you the important things you would otherwise only see.
- **1.2.4 Captions (Live)** (Level AA). No Face Up rule. Scanner: no check. The rest is decided by a person. Manual test: During a live video broadcast with sound, check captions appear and keep up with what is said. A short delay is fine.
- **1.2.5 Audio Description (Prerecorded)** (Level AA). No Face Up rule. Scanner: no check. The rest is decided by a person. Manual test: Play each recorded video. Check there is an audio description, a spoken account of the important things that happen on screen, so someone who cannot see it can follow along. If the normal soundtrack already explains everything shown, no extra description is needed.
- **1.3.1 Info and Relationships** (Level A). Face Up rules: faceup-fake-heading-or-list. They cover only the failures they describe. Scanner: axe catches broken list and table code and fields with no label. It misses text styled to look like a heading or list, because axe's check for that is experimental and switched off. The rest is decided by the code. Manual test: Turn on a screen reader, the software that reads a page aloud for people who are blind or have low vision. Check it announces headings as headings, lists as lists and tables as tables, and reads the right label for each form field. Text that only looks like a heading or a list on screen does not count.
- **1.3.2 Meaningful Sequence** (Level A). Face Up rules: faceup-visual-order-differs. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: Turn on a screen reader, the software that reads a page aloud for people who are blind or have low vision, and listen to the page from top to bottom. Wherever order matters, such as numbered steps, check the content is read in an order that makes sense, even where the layout on screen places things differently.
- **1.3.3 Sensory Characteristics** (Level A). Face Up rules: faceup-sensory-instructions. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: Read every instruction. Check none relies only on shape, size, position, direction or sound, such as 'press the round button' or 'see the box on the right'. Naming the thing as well, as in 'press the round Start button', is fine.
- **1.3.4 Orientation** (Level AA). Face Up rules: faceup-orientation-locked. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: Turn your phone or tablet between upright and sideways. Check the page works both ways and is not locked to one, unless one direction is essential, as with a piano app.
- **1.3.5 Identify Input Purpose** (Level AA). Face Up rules: faceup-autocomplete-missing. They cover only the failures they describe. Scanner: axe catches autocomplete settings that are not valid. It misses fields with no autocomplete, because telling whose details a field asks for means reading its label. The rest is decided by reading the code across files. Manual test: Find each field that asks for your own details, such as name, email, phone number or address. Check your browser offers to fill it in with the right kind of detail. Browsers also guess from a field's name, so this is only a rough guide, and a developer needs to confirm each field carries the correct setting, such as 'email' for an email field.
- **1.4.1 Use of Colour** (Level A). Face Up rules: faceup-colour-only-signal, faceup-sensory-instructions. They cover only the failures they describe. Scanner: axe catches links in a paragraph that differ only by colour. It misses other colour-only signals, such as a red error border, because telling a signal from decoration takes judgement. The rest is decided by reading the code across files. Manual test: View the page in greyscale, using the colour filter setting most phones and computers have. Check you can still tell links from other text, see which fields have errors, and read every chart and status message without relying on colour.
- **1.4.2 Audio Control** (Level A). Face Up rules: faceup-autoplay-media-no-control. They cover only the failures they describe. Scanner: axe catches audio that plays by itself for more than three seconds, and Face Up's check finds video playing on load with no way to pause it. It misses media that starts later, such as when you scroll to it. The rest is decided by the code. Manual test: Load the page. If any sound starts by itself and lasts more than three seconds, check there is a way to pause or stop it, or to change its volume separately from your device's volume.
- **1.4.3 Contrast (Minimum)** (Level AA). Face Up rules: faceup-placeholder-as-label. They cover only the failures they describe. Scanner: axe measures the contrast of text against its background. It cannot judge text over images or gradients, so a person must check those. The rest is decided by the running page. Manual test: Use a free contrast checker, a tool where you pick the text colour and the background colour. Check each kind of text has a contrast ratio, a measure of how much it stands out, of at least 4.5 to 1, or 3 to 1 for large text (roughly 24 pixels, or 19 pixels if bold). Logos, decorative text and text in disabled controls are exempt.
- **1.4.4 Resize Text** (Level AA). Face Up rules: faceup-reflow-horizontal-scroll. They cover only the failures they describe. Scanner: axe catches pages that stop people zooming. It does not enlarge text and recheck the page, so a person must zoom to 200 percent. The rest is decided by the running page. Manual test: Zoom the browser to 200 percent: hold Ctrl (Command on a Mac) and press + until it shows 200%. Check all text gets bigger and nothing is cut off, overlapping or impossible to use. Captions and images of text are exempt.
- **1.4.5 Images of Text** (Level AA). No Face Up rule. Scanner: no check. The rest is decided by a person. Manual test: Look for words that are part of a picture, such as a banner saved as an image. Check real text is used instead, unless it is a logo or the exact look is essential.
- **1.4.10 Reflow** (Level AA). Face Up rules: faceup-reflow-horizontal-scroll. They cover only the failures they describe. Scanner: Face Up's check opens the page 320 pixels wide and finds content that makes it scroll sideways or is cut off. It skips images, tables, code and carousels, and cannot tell a map that needs scrolling both ways from a mistake. The rest is decided by the running page. Manual test: In a browser window about 1280 pixels wide, the size of a typical laptop screen, zoom to 400 percent, which matches a screen 320 pixels wide. Check the content fits in one column and you only scroll up and down, never sideways. Maps, data tables and other content that needs two dimensions are exempt.
- **1.4.11 Non-text Contrast** (Level AA). Face Up rules: faceup-nontext-contrast. They cover only the failures they describe. Scanner: Face Up's check measures the edges of text fields. It misses select menus, icons, switches, checkbox states and focus outlines. The rest is decided by the running page. Manual test: With a contrast checker, compare each part you need to see to use a control, such as a text box border, a checkbox, an icon button or the keyboard focus highlight, against the colours next to it, and do the same for the important parts of charts. Check each is at least 3 to 1. Disabled controls are exempt.
- **1.4.12 Text Spacing** (Level AA). Face Up rules: faceup-text-spacing-clipped. They cover only the failures they describe. Scanner: axe catches spacing set directly on an element and marked !important, which a person's own spacing settings cannot override. It misses text cut off by larger spacing, because the scanner does not apply larger spacing and recheck the page. The rest is decided by the running page. Manual test: Use a text spacing bookmarklet, a browser bookmark that changes the spacing when you click it. It sets line height to 1.5 times the text size, space after paragraphs to 2 times, letter spacing to 0.12 times and word spacing to 0.16 times. Check no text is cut off or overlaps other text.
- **1.4.13 Content on Hover or Focus** (Level AA). Face Up rules: faceup-hover-content-not-dismissible. They cover only the failures they describe. Scanner: no check. The rest is decided by the running page. Manual test: Point at, or tab to, each item that shows extra content such as a tooltip. Check three things: you can close the extra content without moving the pointer or keyboard, usually with the Escape key; you can move the pointer onto it without it vanishing; and it stays until you move away, close it, or it no longer applies. Error messages and content that covers nothing else do not need the Escape check.
- **2.1.1 Keyboard** (Level A). Face Up rules: faceup-div-as-button. They cover only the failures they describe. Scanner: The scanner finds clickable elements the keyboard cannot reach, and axe finds scrolling areas the keyboard cannot reach. It does not try every control with the keyboard, so a person must. The rest is decided by reading the code across files. Manual test: Put the mouse aside. Use Tab to move between items, Enter or Space to press them, and the arrow keys inside menus. Check you can reach and use every link, button, menu and control with the keyboard alone. Features that depend on the path of your movement, such as freehand drawing, are exempt.
- **2.1.2 No Keyboard Trap** (Level A). Face Up rules: faceup-keyboard-trap. They cover only the failures they describe. Scanner: Face Up's check presses Tab through the page and reports focus that cycles through the same controls with no way out. It tests the page as it loads, not pickers or dialogs opened by a click. The rest is decided by the running page. Manual test: Press Tab to move forward through the whole page and Shift+Tab to move back. Check you can always move into and back out of every part, including pop-up windows and embedded players. If leaving needs anything other than Tab, the arrow keys or Escape, the page must tell you how.
- **2.1.4 Character Key Shortcuts** (Level A). Face Up rules: faceup-single-key-shortcut. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: Find any keyboard shortcut that uses one letter, number or symbol key on its own, without Ctrl, Alt or Command. Check that you can turn it off or change it to include one of those keys, or that it works only while the related control is selected.
- **2.2.1 Timing Adjustable** (Level A). Face Up rules: faceup-timeout-no-warning. They cover only the failures they describe. Scanner: axe catches pages that refresh or redirect on a timer. It misses session timeouts, because they are set in app or server code and the browser check does not wait for them. The rest is decided by reading the code across files. Manual test: Find any time limit, such as a session that logs you out or a form that expires. Check you can turn it off, set it to at least ten times as long, or get a warning with at least 20 seconds to extend it with a simple action such as pressing a key. Real-time events such as auctions, limits that are essential, and limits over 20 hours are exempt.
- **2.2.2 Pause, Stop, Hide** (Level A). Face Up rules: faceup-autoplay-media-no-control. They cover only the failures they describe. Scanner: axe catches blink and marquee elements, outdated code for blinking and scrolling text, and Face Up's check finds video that plays on load with no way to pause it. It misses carousels and other content a script moves. The rest is decided by reading the code across files. Manual test: Find anything that moves, blinks, scrolls or updates by itself, such as a carousel, animation or live news feed, and runs alongside other content. Moving or blinking content that lasts more than five seconds needs a way to pause, stop or hide it. Content that updates by itself needs a way to pause, stop or hide it, or to control how often it updates.
- **2.3.1 Three Flashes or Below Threshold** (Level A). No Face Up rule. Scanner: no check. The rest is decided by a person. Manual test: Watch any flashing or quickly changing content, including video. Check nothing flashes more than three times in any one second. If something does, the flashes must be small and dim enough to stay under the safety limits, which needs a specialised checking tool to measure.
- **2.4.1 Bypass Blocks** (Level A). Face Up rules: faceup-skip-link-missing. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: Load the page and press Tab once. Check a link such as 'Skip to main content' appears, or that the page has headings or marked regions a screen reader can jump between. Either lets people get past menus that repeat on every page.
- **2.4.2 Page Titled** (Level A). Face Up rules: faceup-page-title-generic. They cover only the failures they describe. Scanner: axe checks whether the page has a title, and Face Up flags template titles such as "Vite App" and pages that share one. Neither can check whether the title is correct. The rest is decided by a person. Manual test: Read the title on the browser tab. Check it describes what this page is about or what it is for, such as 'Checkout - Shop name'. The shop name on its own is not enough.
- **2.4.3 Focus Order** (Level A). Face Up rules: faceup-focus-order-jumps. They cover only the failures they describe. Scanner: no check. The rest is decided by the running page. Manual test: Press Tab to move through the page and watch the keyboard focus, the highlight that shows which item the keyboard will act on. Check it moves in an order that makes sense for reading and using the page.
- **2.4.4 Link Purpose (In Context)** (Level A). Face Up rules: faceup-control-missing-name, faceup-vague-link-text. They cover only the failures they describe. Scanner: The scanner finds links with no name and links that only say "click here" or "read more". It cannot judge whether other link text says where the link goes. The rest is decided by reading the code across files. Manual test: Read each link together with the sentence, paragraph, list item or heading it sits in. Check you can tell where it goes or what it does.
- **2.4.5 Multiple Ways** (Level AA). Face Up rules: faceup-single-way-to-page. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: Check there are at least two ways to find each page, such as a menu and a search box, or a menu and a site map. Pages that are a step in a process, such as checkout, are exempt.
- **2.4.6 Headings and Labels** (Level AA). Face Up rules: faceup-vague-heading-or-label. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: Read each heading and each form field label. Check it tells you what the section is about or what to enter.
- **2.4.7 Focus Visible** (Level AA). Face Up rules: faceup-focus-not-visible. They cover only the failures they describe. Scanner: The scanner finds styles that remove the focus outline, and in a browser it finds controls that look the same with and without focus. It misses some custom switches, and leaves text fields that may show focus only by the cursor to a person. The rest is decided by the running page. Manual test: Press Tab to move through every link, button and field. Check you can always see which one is selected, usually shown by an outline or highlight.
- **2.4.11 Focus Not Obscured (Minimum)** (Level AA). Face Up rules: faceup-focus-obscured-sticky. They cover only the failures they describe. Scanner: Face Up's check finds controls fully covered by something solid pinned to the screen, such as a cookie bar, when the keyboard reaches them. It checks one window size and only tabs forward. The rest is decided by the running page. Manual test: Press Tab to move through the page, especially near headers, footers, cookie banners or chat buttons that stay on screen as you scroll. Check the selected item is never completely hidden behind them.
- **2.5.1 Pointer Gestures** (Level A). Face Up rules: faceup-pointer-gesture-no-alternative. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: For anything that uses a swipe, a pinch, a two-finger gesture or a drawn path, check the same thing can be done with one finger or pointer without tracing a path, such as by tapping buttons. Gestures that are essential, such as a signature, are exempt.
- **2.5.2 Pointer Cancellation** (Level A). Face Up rules: faceup-action-on-press. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: Press and hold on a button, then move the pointer or finger off it before letting go. Check nothing happens. If an action happens as soon as you press down, check you can undo it or cancel it before it finishes. Actions where pressing down is essential, such as keys on a piano app, are exempt.
- **2.5.3 Label in Name** (Level A). Face Up rules: faceup-label-not-in-name. They cover only the failures they describe. Scanner: axe finds buttons and links whose name leaves out their visible text. For other controls, the skill compares the visible label with the name. The rest is decided by the code. Manual test: Turn on a screen reader, the software that reads a page aloud for people who are blind or have low vision, and move to each button, link and field that shows words. Check the name it reads out includes those visible words. Voice control software works as a second check: saying the visible words should activate the control.
- **2.5.4 Motion Actuation** (Level A). Face Up rules: faceup-motion-only-input. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: For any feature that works by shaking or tilting your device, or by moving in front of a camera, check there is also a button or other control that does the same thing, and a way to switch off the motion response.
- **2.5.7 Dragging Movements** (Level AA). Face Up rules: faceup-dragging-no-alternative. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: For anything you move by dragging, such as reordering a list or moving a slider, check you can also do it with single taps or clicks, such as up and down buttons or tapping a point on the slider. Dragging that is essential is exempt.
- **2.5.8 Target Size (Minimum)** (Level AA). Face Up rules: faceup-target-too-small. They cover only the failures they describe. Scanner: axe measures each control as drawn and finds targets smaller than 24 by 24 pixels that sit too close to others. Targets it cannot decide are listed for a person. The rest is decided by the running page. Manual test: Measure each button, link and control you click or tap, using a browser ruler extension. Check it is at least 24 by 24 CSS pixels, the browser's own unit of size, or that a 24-pixel circle centred on it does not overlap any other target or its circle. Links inside sentences, and targets with a same-purpose version on the page that is big enough, are exempt.
- **3.1.1 Language of Page** (Level A). Face Up rules: faceup-lang-missing. They cover only the failures they describe. Scanner: axe finds a missing or invalid page language. It cannot tell whether the language named is the right one. The rest is decided by the code. Manual test: Right-click the page and choose View page source. Check the html tag near the top includes lang= followed by the right language code, such as en or en-AU. Screen readers use this setting to choose the right pronunciation.
- **3.1.2 Language of Parts** (Level AA). Face Up rules: faceup-lang-of-parts-missing. They cover only the failures they describe. Scanner: axe catches language codes that are not valid. It misses unmarked passages in another language, because spotting them means reading the content. The rest is decided by reading the code across files. Manual test: Find any passage in a different language from the rest of the page, such as a quote in French. Check it is marked with its own language setting. Listening with a screen reader shows this: an unmarked passage is usually read with the wrong pronunciation. Names, technical terms and words that have become part of the surrounding language are exempt.
- **3.2.1 On Focus** (Level A). Face Up rules: faceup-action-on-focus. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: Press Tab to move onto each link, button and field without pressing anything else. Check that landing on it does not open a new page or window, submit a form or move you somewhere else.
- **3.2.2 On Input** (Level A). Face Up rules: faceup-context-change-on-input. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: Change each drop-down list, checkbox, radio button and text field without pressing a submit button. Check nothing opens a new page, submits the form or moves you elsewhere, unless the page told you beforehand that it would.
- **3.2.3 Consistent Navigation** (Level AA). Face Up rules: faceup-nav-order-changes. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: Visit several pages. Check menus and navigation links that repeat across pages stay in the same order each time, unless you changed them yourself. Links may be added or removed, as long as the rest keep their order.
- **3.2.4 Consistent Identification** (Level AA). Face Up rules: faceup-inconsistent-naming. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: Find controls that do the same thing on different pages, such as a search button or a print icon. Check they are labelled consistently, with the same words and icons each time.
- **3.2.6 Consistent Help** (Level A). Face Up rules: faceup-consistent-help. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: Where help is offered on several pages, such as contact details, a chat button or a link to a help page, check it appears in the same place relative to the rest of the page each time. A site does not have to offer help, but help that repeats must stay in place.
- **3.3.1 Error Identification** (Level A). Face Up rules: faceup-colour-only-signal. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: Fill in a form with mistakes, such as a missing required field or a badly formatted email address, and submit it. Check each mistake is described in words and the message makes clear which field is wrong. Colour or an icon alone is not enough.
- **3.3.2 Labels or Instructions** (Level A). Face Up rules: faceup-placeholder-as-label. They cover only the failures they describe. Scanner: Face Up's check finds text fields whose only label is the placeholder. It cannot tell this from a visible label that is not linked to its field, and it does not judge whether labels are clear. The rest is decided by reading the code across files. Manual test: Check every field, checkbox and choice you fill in has a label or instructions telling you what to enter, including any required format, such as a date pattern.
- **3.3.3 Error Suggestion** (Level AA). Face Up rules: faceup-error-not-identified. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: Make mistakes in a form and submit it. Where the fix is known, check the message says how to correct it, such as 'Enter the date as DD/MM/YYYY'. Messages may leave out a suggestion that would weaken security or defeat the purpose of the form, such as revealing which part of a login was wrong.
- **3.3.4 Error Prevention (Legal, Financial, Data)** (Level AA). Face Up rules: faceup-error-prevention-destructive. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: For any step that makes a legal agreement, takes payment, changes or deletes your saved data, or submits test answers, check at least one of these is true: you can undo it; the site checks your entries for mistakes and lets you fix them; or you can review, correct and confirm everything before it is final.
- **3.3.7 Redundant Entry** (Level A). Face Up rules: faceup-back-discards-data, faceup-redundant-entry-multistep. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: Go through a process with several steps, such as a checkout. Where a later step asks for something you already gave, check it is filled in for you or offered as a choice, such as a 'Same as delivery address' tick box. Asking again is allowed for security, such as confirming a new password, when re-entering is essential, or when the earlier answer is no longer valid.
- **3.3.8 Accessible Authentication (Minimum)** (Level AA). Face Up rules: faceup-cognitive-auth-test, faceup-paste-blocked-password. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: Log in and go through any sign-up or verification steps. Check no step makes you remember, retype or solve something, such as retyping a code or solving a puzzle, unless you can paste, let a password manager fill it in, or choose another method. Picking out objects, such as 'select the pictures with a bus', and recognising content you provided yourself are allowed.
- **4.1.2 Name, Role, Value** (Level A). Face Up rules: faceup-aria-references-missing-id, faceup-control-missing-name, faceup-div-as-button. They cover only the failures they describe. Scanner: The scanner finds buttons and links with no name, clickable elements that are not buttons, and references to ids that are not on the page, and axe adds its checks of roles, states and names. It does not operate custom controls to test them. The rest is decided by the code. Manual test: Turn on a screen reader, the software that reads a page aloud for people who are blind or have low vision, and move to each button, link, field and custom control such as a menu or tab. Check it reads a name (what the control is called), a role (what kind of control it is, such as 'button' or 'checkbox') and its current state (such as 'checked' or 'expanded'), and that the state it reads changes when you change it.
- **4.1.3 Status Messages** (Level AA). Face Up rules: faceup-async-status-not-announced, faceup-toast-only-error. They cover only the failures they describe. Scanner: no check. The rest is decided by reading the code across files. Manual test: Turn on a screen reader, the software that reads a page aloud for people who are blind or have low vision. Cause loading, success and error messages, for example by saving a form or adding an item to a cart. Check each message is read out without the keyboard focus, the highlight that shows which item the keyboard will act on, jumping to it.
